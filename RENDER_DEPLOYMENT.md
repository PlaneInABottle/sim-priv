# Render Deployment Guide

This guide explains how to deploy Sim Studio to [Render.com](https://render.com).

## Prerequisites

- A Render.com account
- A GitHub repository with this codebase
- PostgreSQL with pgvector extension (Render provides this)

## Quick Deploy with Blueprint

The easiest way to deploy is using Render's Blueprint feature:

1. Fork or push this repository to your GitHub account
2. Go to [Render Dashboard](https://dashboard.render.com)
3. Click **New** → **Blueprint**
4. Connect your GitHub repository
5. Render will detect `render.yaml` and configure services automatically
6. Review the configuration and click **Apply**

## Services Overview

The blueprint creates three services:

| Service | Type | Description |
|---------|------|-------------|
| `simstudio` | Web Service | Main Next.js application (port 3000) |
| `realtime` | Web Service | Socket.io server for real-time features (port 3002) |
| `db-migrations` | Job | Runs database migrations on deploy |
| `simstudio-db` | PostgreSQL | Database with pgvector support |

## Environment Variables

### Required Variables (Auto-Generated)

These are automatically generated by Render:

| Variable | Description |
|----------|-------------|
| `DATABASE_URL` | PostgreSQL connection string (from database) |
| `BETTER_AUTH_SECRET` | Authentication secret (auto-generated) |
| `ENCRYPTION_KEY` | Encryption key for sensitive data (auto-generated) |
| `INTERNAL_API_SECRET` | Internal API authentication (auto-generated) |
| `API_ENCRYPTION_KEY` | API encryption key (auto-generated) |

### Required Variables (Manual Configuration)

After deployment, configure these in the Render dashboard:

| Variable | Description | Example |
|----------|-------------|---------|
| `BETTER_AUTH_URL` | Your app's public URL | `https://simstudio.onrender.com` |
| `NEXT_PUBLIC_APP_URL` | Same as above | `https://simstudio.onrender.com` |
| `SOCKET_SERVER_URL` | Realtime service URL | `https://realtime.onrender.com` |
| `NEXT_PUBLIC_SOCKET_URL` | Same as above | `https://realtime.onrender.com` |

### Optional Variables

| Variable | Description | Default |
|----------|-------------|---------|
| `COPILOT_API_KEY` | API key for Copilot features | - |
| `OLLAMA_URL` | Ollama server URL for local models | - |
| `VLLM_BASE_URL` | vLLM server URL | - |

## Post-Deployment Setup

### 1. Configure URLs

After your services are deployed:

1. Go to your `simstudio` service in Render dashboard
2. Copy the service URL (e.g., `https://simstudio-xxxx.onrender.com`)
3. Add/update these environment variables:
   - `BETTER_AUTH_URL` = your service URL
   - `NEXT_PUBLIC_APP_URL` = your service URL
4. Do the same for the `realtime` service URL:
   - `SOCKET_SERVER_URL` = realtime service URL
   - `NEXT_PUBLIC_SOCKET_URL` = realtime service URL
5. Redeploy both services

### 2. Enable pgvector Extension

Render's PostgreSQL includes pgvector. The migrations will automatically set up the extension.

### 3. Custom Domain (Optional)

1. Go to your service's **Settings** → **Custom Domain**
2. Add your domain and configure DNS
3. Update the URL environment variables to use your custom domain

## Secrets Management

### Best Practices

1. **Never commit secrets** - All sensitive values should be environment variables
2. **Use Render's secret management** - Add secrets in the dashboard, not `render.yaml`
3. **Rotate secrets periodically** - Generate new values for production keys

### Generating Secure Secrets

For manual secret generation:

```bash
# Generate a 32-byte hex secret
openssl rand -hex 32
```

## Database Management

### Accessing the Database

1. Go to your database in Render dashboard
2. Use the **Connect** button for connection details
3. Use a tool like `psql` or pgAdmin

### Backup and Restore

Render provides automatic daily backups for paid database plans. Manual backups:

```bash
# Export
pg_dump $DATABASE_URL > backup.sql

# Import
psql $DATABASE_URL < backup.sql
```

## Troubleshooting

### Service Won't Start

1. Check the **Logs** tab in Render dashboard
2. Verify all required environment variables are set
3. Ensure the database is healthy

### Database Connection Issues

1. Check if `DATABASE_URL` is correctly configured
2. Verify the database is running (check database service status)
3. Ensure migrations completed successfully

### Health Check Failures

The services have health endpoints:
- `simstudio`: `/` (root path)
- `realtime`: `/health`

If health checks fail:
1. Check service logs for errors
2. Verify memory limits aren't exceeded
3. Check if dependencies (database) are healthy

### Memory Issues

Default plans have limited memory. If you see OOM errors:
1. Upgrade to a higher plan
2. Optimize application memory usage
3. Check for memory leaks in logs

## Scaling

### Horizontal Scaling

Upgrade your plan to add more instances:
1. Go to service **Settings** → **Instance Type**
2. Choose a plan with more instances

### Database Scaling

For production workloads:
1. Upgrade database plan for more connections and storage
2. Consider adding read replicas for heavy read workloads

## Cost Optimization

### Development/Staging

Use starter plans for non-production environments.

### Production

- `simstudio`: Standard plan recommended (more memory, better performance)
- `realtime`: Starter plan usually sufficient
- `simstudio-db`: Standard plan for production workloads

## Updating

To update your deployment:

1. Push changes to your GitHub repository
2. Render will automatically redeploy (if auto-deploy is enabled)
3. Or manually trigger a deploy from the dashboard
